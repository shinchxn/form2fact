2. PROBLEM BEING SOLVED
-----------------------
Institutional document scrutiny across engineering colleges, regulatory filings, and accreditation submissions requires reviewing hundreds of pages across disparate PDFs (land lease deeds, municipal site plans, fire safety NOCs, faculty registries, and statutory affidavits). 

Manual verification suffers from severe cognitive bottlenecks:
- Information fragmentation: Key claims declared in applications are buried across dozens of scanned schedules.
- Subtle cross-document discrepancies: Dates, names, acreages, and tenure terms differ between applicant declarations and underlying legal deeds.
- Scanned photocopy degradation: Unindexed bitmaps make text extraction and citation tracing laborious.
- Review inconsistency: Different scrutiny officers apply subjective criteria without standardized audit trails.

Form2Fact solves this by delivering an evidence-grounded document intelligence platform that extracts structured claims from applications, links them to exact page-level evidence in supporting legal documents, identifies discrepancies via calibrated 5-class classification, and routes non-trivial findings to authorized human reviewers.

4. HOW FORM2FACT WORKS
----------------------
1. Authorized Ingestion: Institutional dossiers (PDF applications and evidentiary annexures) are ingested with SHA-256 physical checksum verification and provenance registration.
2. Document Intelligence: PyMuPDF and OCR pipelines extract text, coordinates, and structured statutory fields (dates, acreages, entity titles, approval references).
3. Pairwise Field Comparison: Sponsoring declarations are paired against corresponding evidentiary clauses.
4. Five-Class Discrepancy Classification: Pairs are classified into MATCH, MISMATCH, MISSING, UNCERTAIN, or NOT_COMPARABLE.
5. AI Reasoning & Grounded Explanation: Permitted claim/evidence excerpts are sent to BharatCode Model API (qwen-3.8-27b) to generate evidence-grounded reasoning explaining the finding.
6. Human Review & Adjudication: Discrepancies and uncertainties are routed to authorized human reviewers; disagreements undergo double-blind independent adjudication.
7. Auditable Reporting: Findings with exact document names, page citations, and tamper-resistant audit logs are generated for institutional decision-makers.

6. BHARATCODE API INTEGRATION
-----------------------------
Form2Fact integrates directly with the official BharatCode Model API infrastructure:
- Base URL: https://bharatcode.ai/api/model/v1
- Service Class: server/modules/explanation/bharatCodeService.ts
- Endpoints Supported:
  * POST /api/v1/findings/:id/explain (Generates explanation for existing finding)
  * POST /api/v1/ai/bharatcode/explain (Arbitrary pairwise comparison explanation)
- Outbound Protocol: REST POST /chat/completions with Bearer authentication and json_object response format
- Privacy Safeguard: Automatic client-side PII redaction (Aadhaar, PAN, phone, email, bank accounts) prior to outbound transmission.


7. MODEL AND API USAGE
----------------------
- Model Name: qwen-3.8-27b (BharatCode Qwen 3.8 27B)
- Fallback Model: deepseek-v4.1-flash (configurable via BHARATCODE_MODEL)
- Parameters: temperature=0.1 (deterministic scrutiny), response_format={ type: "json_object" }
- Payload Schema:
  {
    "summary": "1-2 sentence executive finding summary",
    "classification_context": "MATCH | MISMATCH | MISSING | UNCERTAIN | NOT_COMPARABLE",
    "reasoning": "Evidence-grounded explanation linking claim to cited clauses",
    "evidence_references": [{ "documentName": "...", "pageNumber": 1, "citedText": "..." }],
    "uncertainties": ["Explicit ambiguities or data limitations"],
    "requires_human_review": boolean
  }


8. HOW THE API CONTRIBUTES TO THE APPLICATION
---------------------------------------------
While Form2Fact's deterministic rules and pairwise classifier identify the mathematical and lexical presence of a discrepancy, the BharatCode Qwen 3.8 27B model provides the crucial explanatory bridge for human scrutiny officers:
- Synthesizes complex legal clauses (e.g., explaining why a 15-year lease tenure fails a declared 30-year requirement).
- Explains legal entity naming variations (e.g., trust name variations vs corporate conflicts).
- Identifies specific textual ambiguities requiring physical inspection.
- Provides immediate evidence-grounded summaries that save scrutiny committees up to 70% of manual reading time.


9. EXISTING ML CLASSIFIER AND ITS ROLE
---------------------------------------
Form2Fact maintains a calibrated hybrid pairwise field mismatch classifier (V2 Champion):
- Taxonomy: 5-Class [MATCH, MISMATCH, MISSING, UNCERTAIN, NOT_COMPARABLE]
- Invariant: Low lexical similarity is NOT treated as proof of contradiction; unverified ambiguity strictly abstains to UNCERTAIN.
- Hierarchy: The classifier and regulatory rules remain 100% authoritative. BharatCode cannot override the classification label or approve/reject institutions.


10. HUMAN-IN-THE-LOOP SAFEGUARDS
--------------------------------
- Zero Autonomous Decisions: The software never approves, rejects, or sanctions an institution. All determinations belong exclusively to authorized human committees.
- Hallucination Filter: The service cross-validates all evidence references returned by the LLM against actual ingested document names and pages; unverified citations are stripped immediately.
- Classifier Override Guard: If the LLM proposes a divergent label, the service forces the authoritative classifier result, flags the discrepancy, and mandates human review.
- Double-Blind Adjudication: Conflicting reviewer annotations are automatically isolated and routed to a neutral senior adjudicator.


11. SECURITY AND PRIVACY PRINCIPLES
-----------------------------------
- Zero Key Exposure: BHARATCODE_API_KEY is restricted strictly to backend environment variables; never exposed to browser bundles, React code, or client logs.
- Sanitized Error Handling: Secret tokens are scrubbed from all outbound error messages and logs.
- Data Minimization: Only relevant claim/evidence excerpts (max 400 chars) are transmitted; full document files are never sent over external APIs.
- Tenant Isolation: Regional multi-tenant scoping ensures organizations cannot view or explain cross-tenant dockets (HTTP 403 Forbidden).
- 15 Export Firewall Gates: Synthetic, unverified, or revoked reviewer records are permanently blocked from gold-standard datasets.


12. SETUP INSTRUCTIONS
----------------------
Prerequisites: Node.js v20+, npm v10+, Python 3.10+ (optional for AI microservice)

1. Clone repository:
   git clone https://github.com/shinchxn/form2fact.git
   cd form2fact

2. Install dependencies:
   npm install

3. Configure environment:
   cp .env.example .env
   # Add your BharatCode API key in .env:
   # BHARATCODE_API_KEY=bc_live_your_actual_key_here

4. Run test suites:
   npx tsx server/tests/bharatCodeIntegration.test.ts
   npm test

5. Start development servers:
   # Backend API Server:
   npm run server
   # Frontend Dashboard:
   npm run dev
